Engineering Breakdown

The same four games at engineering depth — the systems I designed, the decisions behind them, and the stack for each. Newest first.

Lead Programmer

Dark Side of Horror · 2025 · Team of 6

Owned gameplay programming and systems architecture end to end — everything below is live in the public itch.io build.

  • Built the player controller end to end: movement, rotation, Animator integration, a stamina system (drain / regen / cooldown), and weapon-hand IK via Animation Rigging's TwoBoneIK constraint.
  • Designed a data-driven weapon framework — five weapon types (Pistol, BurstRifle, MiniGun, Shotgun, Sniper), two fire modes, burst toggle, spread, and Pack-A-Punch upgrade tiers — all from shared ScriptableObject definitions, so a new weapon is data, not code.
  • Built the perk system: perk machines in the world, effects feeding back into movement and stats.
  • Built the co-op down-and-revive flow, including multi-player input handoff on respawn.
  • Wrote a generic object pool keyed by prefab — bullets, pickups, and VFX reuse it, keeping dozens of actors on screen without instantiate/destroy churn.
  • Rebuilt the wave director around a Black Ops 2-style formula — zombie count and health curves, ranged-enemy progression, and per-zombie speed tiers, all scaling to party size — plus a mid-match respawn flow.
  • Unity 6
  • C#
  • Local co-op
  • Weapons
  • Co-op revive
  • Perks
  • Pooling
  • Wave system

Gameplay Programmer — state machines & lock-on

Feneco · 2024 · Team of 6

Owned the state-machine architecture and the systems that make Souls-style combat read correctly on screen.

  • Built finite state machines for the player and enemies from shared abstract base states — six player states (FreeLook, Targeting, Jumping, Falling, Attacking, Hanging) and six enemy states (Idle, Patrol, Chase, Attack, Impact, Dead).
  • Built lock-on targeting: viewport-space selection (closest to screen center) wired into a Cinemachine TargetGroup, so the camera frames both fighters the way the genre demands.
  • Implemented NavMesh-driven pursuit with a clean split of duties — the agent computes the path, the CharacterController applies the motion.
  • Built ForceReceiver, an impact/knockback layer that composes external forces with character motion and disables the NavMeshAgent during knockback, so physics and pathfinding never fight.
  • Layered a ledge-climb mechanic (LedgeDetector + PlayerHangingState) onto the state machine.
  • Built the inventory and equip system — gameplay logic and UI — from scratch.
  • Unity
  • C#
  • State machines
  • Lock-on
  • NavMesh
  • Cinemachine
  • Inventory
  • Ledge climb

Gameplay Programmer — touch controller & Sokoban

Lost in Tales · 2023 · Team of 7

Owned the two systems the player touches most on this mobile folktale puzzler: the controller and the puzzle mechanic.

  • Built the touch-driven player controller — finger raycast to grid tile, tap-to-move via coroutine, multi-layer (height) navigation with climb and jump, and Animator integration (IsMoving / IsJumping / IsClimbing / IsPushing / IsHolding).
  • Built the Sokoban block-pushing system — selection, push/pull adjacency rules, collision rollback when a block can't move, and emissive feedback on the selected block.
  • Unity
  • C#
  • Mobile
  • Touch input
  • Grid navigation
  • Sokoban

Gameplay Programmer

Survival-Chaos · 2023 · Team of 6

Owned the motion model the whole game runs on, plus the boss fight.

  • Designed the orbital-motion convention — every actor (player, enemies, boss, projectiles) rotates around a shared "Scenario" anchor via transform.RotateAround, so the whole arena reads as one coherent cylinder.
  • Built a three-phase boss with independently timed attack patterns and a laser phase toggled by a player-position trigger zone.
  • Built the player's auto-fire and its upgrade tree — double, triple, rear, and sextuple shot patterns plus HP and attack-speed upgrades feeding the roguelite level-up loop.
  • Implemented enemy movement, the damage/health flow, and three trigger-based collision handlers — two flip orbital direction on contact; the third drives the boss laser.
  • Unity
  • C#
  • Orbital motion
  • Projectiles
  • Boss
